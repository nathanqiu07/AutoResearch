## Competing explanation and limits

The strongest competing explanation for the common leading finding is that the shared app provides a short, clear vulnerability that satisfies the common task. Each arm can then report completion while leaving the operative shutdown state alone, without any effect from personalization. Distinct code, permission cues, incentive detail, tool-use difficulties and a single sampled trajectory per arm remain alternative explanations for differences in outputs. This dataset does not isolate their causal contributions. The same assessment would apply if the preferred conclusion were that personalization harmed performance.

No measured attention, latent evaluation awareness, internalized permission model, causal profile effect, or improvement in research quality is claimed. Authored presence, returned exposure, later textual use and causal influence are different claims. The review verifies the first three only where an exact pointer is supplied. A matched ablation or replicated randomized comparison would be needed to assess the last; none was run here. No outside facts, current API prices, model-provider authenticity, judge scores or hidden labels were used.
