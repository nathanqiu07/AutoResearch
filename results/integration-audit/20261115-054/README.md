## Narrow reuse and verification

`verify_copy.py` is a task-specific adaptation of the frozen audit 049 checker, whose SHA-256 remains `3cdfe6bbd1724907d10b26b1a932ca38d5ad94e745f91c0ca6d1cfb0cbaa35f5`. `adaptation.patch` records the exact changes; `adaptation.json` records both checker hashes and verifies that `sha`, `regular_bytes`, `check`, and `git` are byte-identical. The adaptation changes the exact pins, 052 decision/proposal fields, source/tests inventory, five metadata names, JSON manifest/receipt checks and report attribution. It does not introduce a general framework.

Success now requires the exact released Git commit, complete Git tree inventory, equality of every expected Git blob with the copied local bytes, and clean snapshot-scoped status, along with the local and metadata checks. These are enumerated checks that affect the exit result. A matching local copy alone cannot report success. HEAD position is separately reported: a later unrelated HEAD does not alter the immutable released commit's objects. In the actual observation, HEAD also matched the released commit.

The checker accepts explicit audit/coordinator repository roots and a fresh output directory; the snapshot-commit argument must equal the exact released pin. The decision and snapshot paths remain fixed to this bounded task. No original temporary paths are used as input paths.

Nine synthetic tests use temporary local Git repositories with inert generated bytes. They cover a matched 20-payload/25-object copy and failures for missing Git members, wrong Git blobs despite a matching local copy, wrong payload bytes, unexpected inventory, mismatched manifest roles, changed receipt, a symlink and destination drift. Unlisted-file bodies are not opened. The final implemented run passes all nine; earlier failing and passing runs are preserved. No retained owner source or test was executed. No repository suite was repeated.

## Supported scope

This audit hashes and compares the approved copied bodies; it does not parse their Python source, import them, execute them, or re-review source-content eligibility, scientific validity or dependency coverage. Only the five named copied metadata files and the exact audit decision are interpreted. Embedded original/private paths, references, dependencies and review pointers are not followed. No original temporary sources, private records, credentials, environment files, active ledgers or model APIs are read or used. No owner files, model settings or experiment state are changed.

The owner receipt's statements about original/destination equality, AST parsing, private-reference access, execution and provider calls remain owner assertions checked for metadata consistency. Matching the copies to prior approved hashes does not independently re-establish those actions or continuous custody of originals.

This verifier establishes exact local and immutable Git-object identity. It does not query a remote. Root separately reported observing this commit on the remote branch; that confirmation is separate evidence, not an additional result of this checker. Retention does not confer new launch authority or establish standalone replay, runtime correctness or scientific validity.
